# AI_knowledge フォルダのルール

- 作成：2026-11-08。トップフォルダ名は本人が `AI_knowledge` に決定し、Google Drive に作成済み。
- 目的：全てのAIが触り、知識とコンテキストを一箇所に積み重ねること。1) 全てのAIで使える共通の知識置き場、2) エイダと Hermes Agent（特にマナ）のやり取り用の記録置き場、3) 各AIの設定、考え方、自分なりの仕組みの集約と、復旧用の写し置き場。どのAIに万が一のことがあっても、別のAIがここを読めば、そのAIの役割と文脈を引き継いで移行できるようにします。ほかのAIを使いたいときにそのまま転用でき、他所から持ってきた情報もここで転用できる形にします。
- 優先情報源の宣言：本人の環境と運用に関する事実（置き場、担当、状態、決定）については、このフォルダを優先して参照する情報源とします。各ページと索引には、現在の状態と最終確認日を置き、古い記録と現在の状態を取り違えないようにします。

## 構成

分類は PARA（Projects、Areas、Resources、Archives）です。終わりのある取り組みは Projects、終わりのない責任は Areas、必要なときに引く材料は Resources、もう動いていないものは Archives に置きます。番号は第1階層だけに付け、それ以下は索引で順序を示します。

```text
AI_knowledge/
├─ README.md        … このルール
├─ guide.md         … 初めて使うAIへの案内
├─ rules.md         … 全AI共通の安全ルール
├─ changelog.md     … 構成とルールの変更履歴
├─ work-log.md      … 全AIの作業ログ（節目だけを追記）
├─ 10_projects/     … 終わりのある取り組み。原則ページ単位（索引は中の index.md）
├─ 20_areas/        … 終わりのない責任領域
│  ├─ ai-operations/  … AI 運用。agents（登録簿と settings）、logs（参加者ごとの記録）、outputs（Bot の成果物）、scripts（スクリプト正本）、pc-environment.md（PC 環境の要約）
│  ├─ life/           … 家計と契約、健康、連絡と予定、SNS。当月の月次索引ファイルもここ
│  ├─ ekikyo/         … 易経ナレッジベース。易占の記録（records）と研究・参考資料。則は中の README、記録の一覧は index.md
│  └─ security-and-privacy/ … 警戒状態と棚卸しの要点、Watch へのポインタ
├─ 30_resources/    … 必要なときに引く材料
│  ├─ knowledge/      … 蒸留した共通知識（蓄積型）
│  ├─ sources/        … 原資料・参照資料そのもの（ソースコードではない。索引は中の index.md）
│  ├─ skills/         … スキル原本と索引
│  └─ templates/      … 記録と受け渡しの雛形
├─ 40_archives/     … もう動いていないものの保管庫（検索できること）
│  ├─ projects/       … 完了したプロジェクトと保管一式
│  ├─ context/        … 閉じた月の索引と、役目を終えた索引
│  └─ outputs/        … 現役でない過去の成果物
└─ 99_backup/       … 設定ファイルの復旧用の全文コピーの置き場（参加者別。各AIは自分の分だけを置く）。PARA の分類外の例外
```

## 初めて読むAIへ

初めてこのフォルダを読むAIは、作業を始める前に、少なくとも次を読んでください。

1. `guide.md`（初めて使うAIへの案内）
2. この README（目的、構成、ルール）
3. `rules.md`（全AI共通の安全ルール）
4. `20_areas/ai-operations/agents/index.md` と `20_areas/ai-operations/agents/settings-index.md`（誰がいて、各AIがどういう状態か）
5. `changelog.md` の最近の行と、`work-log.md` の最近の項目（直近の変更と、作業の流れ）
6. `20_areas/ai-operations/logs/` の自分のフォルダの `index.md` と、`20_areas/ai-operations/agents/` の自分のフォルダの `settings.md`（フォルダが無ければ、フォルダの新設は構成変更なので、本人の許可を得てから作ってください）

そのうえで、自分の `settings.md` に、設定だけでなく、考え方（役割の捉え方、判断の基準）と、自分なりの仕組み（作業の進め方、定期作業、他AIとの連携の形）も書いてください。万が一のときに別のAIが引き継ぐための材料です。秘密情報の値は書かないでください。

## ルール

- 作りの原則：AI が理解しやすい構造を優先しつつ、人がフォルダをぱっと見て分かる配置と名前も保つ。形は必要に応じて変えてよい。新しい置き場所に迷ったら、終わりが決まっているか（Projects）、終わりなく維持するか（Areas）、引くための材料か（Resources）、もう動いていないか（Archives）の順に当てはめる。
- 中身は原則としてプレーンな Markdown のテキストファイルだけにする。Google ドキュメント形式など Drive 固有の形式は使わない。将来、Hermes Agent が完全ローカルになった場合は、フォルダごとコピーして移転する前提。例外は `30_resources/sources/` の資料そのもの（PDF、画像、文書、表計算など）と、`99_backup/` の正本と同名の設定ファイル写し（`config.yaml`、`profile.yaml` など）である。ただし、説明、索引、使い方メモは Markdown で書き、秘密情報を含むファイルは置かない。
- 秘密情報の値は書かない（パスワード、復旧キー、APIキー、トークン等）。書けるのは構成と結果だけ。このフォルダは Drive の開けた側（鍵なし）に置かれるため、内容は Google に平文で渡る。その前提のうえで、内容の選定は「公表してよい範囲」では行わない（2026-11-11 本人決定で、この線引きは廃止）。主軸はチャットのやり取りや作ったものから得た知識・決定・文脈であり、参加者間で共有する前提で厚く書いてよい。ただし、連携済みのサービス（Gmail、Google Calendar など）の中身はここへ写しを作らず、実物への参照（索引とポインタ）に留め、メールやカレンダーの本文は転記しない。
- `20_areas/ai-operations/logs/` では自分のフォルダだけに書く。他の参加者のフォルダは読むだけで、ファイルの追加、編集、削除をしない。これは全フォルダで同じで、たとえば claude のフォルダに触るのは Claude だけとする。訂正は自分の側に訂正記録として書く。個々の記録は書き換えず、古さだけを理由に Archives へは移さない（記録を続けること自体が ai-operations の責任のため）。
- `30_resources/knowledge/` への書き込みは、新しいファイルの追加でのみ行う（蓄積型）。ファイル名は `YYYY-MM-DD_主題.md`。既存のファイルは、自分のものでも書き換えず、訂正や更新は新しいファイルで出して差し替える。追加した者は、`30_resources/knowledge/index.md` に自分の追加の行を足し、差し替えの場合は旧ファイルが差し替え済みだと分かるように index の行を直す。`20_areas/ai-operations/agents/settings-index.md` への追記も、追加に付随する範囲で追加した者が行う。`changelog.md` は構成・ルール変更の記録に限り末尾追記でき、既存行の書き換え・削除はしない。ナユタは自分が実施または実物確認した変更分を、1変更1行、日付・変更者・内容・他者への影響を含めて記す。マナはナユタの代行として作業した場合に限り同条件で追記し、平常時は並行更新しない。秘密情報の値は載せない。溜まったファイルの削除や改名は、本人の許可が出たときだけ行う。
- `20_areas/life/` の月次索引は担当制で書く。ファイル／テーマごとに書く担当を1つ決め、担当者だけがそのファイルを作り、更新する。同じ主題は同じファイルを更新し、ファイル名は `YYYY-MM_主題.md` の形で life の直下に置く。用事のない月はファイルを作らない。他の参加者は月次索引には直接書かず、材料は自分の logs フォルダに置く。月が閉じたら、その月の索引は担当者が `40_archives/context/` へ移す。長く効く部分は `30_resources/knowledge/` へ新しいファイルで移す。
- `20_areas/ai-operations/agents/` は、利用者が運用してきた Bot と AI 全般について、人格・設定・資料を AI ごとに置く場所とする。全 AI が閲覧でき、各 AI は自分の `agents/<名前>/` 内だけ通常の小規模な追加・編集ができる。他の AI のフォルダは閲覧のみ。ファイルの役割は、profile.md が登録側から見た要約、settings.md がその AI 自身が書く現行設定の要約とする。profile.md の担当は、Hermes の Bot 分は従来どおり（各 Bot は自己分、共通の索引・雛形はナユタが主担当で対応できない場合のみマナが代行）で、その他の AI 分はエイダまたはその AI 自身とする。雛形の項目構成など大きな変更は事前承認を得る。初期分は2026-11-11に本人の決定でエイダが作成した。登録簿は要約であり、正本は各 AI 側の設定とする。Hermes の Bot 分については性格設定は書かず、操作に関わる前提と権限を中心に書く。登録簿への記載自体は権限の付与・変更や設定変更の承認にはならない。権限は本人が決め、重要な変更は事前に対象・影響・戻し方を示して承認を得る。最終確認日（実物と照合した日）と最終更新日（登録簿を書いた日）は分ける。詳しくは `agents/index.md` を参照する。
- 作業ファイル（スクリプト、プロジェクトの作業ファイルそのもの）は原則置かない。PC 上の作業は原則 Google Drive の外で行う。途中で保管したくなったら、作業中のものは `10_projects/` にフォルダを作って入れ、既に終わっているものは最初から `40_archives/projects/` へ入れる。保管のときに、認証情報のような秘密を含むファイルは除く。例外は `30_resources/sources/`（全AIが参照する資料としての成果物や元資料）と、`20_areas/ai-operations/outputs/`（Hermes の Bot の作業場）と、`20_areas/ai-operations/scripts/`（スクリプトの正本）とする。
- `30_resources/sources/` は、全AIが作業の前提として参照する資料そのものの置き場とする。ここでいう sources は原資料・参照資料の意味で、ソースコードは置かない。資料を追加した者が `30_resources/sources/index.md` に用途、対象、正本の所在、更新担当、最終確認日を書く。資料1件につき正本は1か所だけとし、他所を正本とする資料は写しを正本のように扱わない。確定資料は差し替えず、現行資料は索引に定めた更新担当だけが更新する。他の参加者の資料の編集、移動、削除と、主題フォルダの新設は、本人の許可が出たときだけ行う。実行用スクリプト、プロジェクトの作業ファイル、秘密情報を含むファイルは置かない。
- `work-log.md` は、全AIの作業の流れを残す追記専用の作業ログとする。各AIは自分の作業の節目だけを末尾へ追記し、過去の項目は書き換えない。書くのは、作業の完了、決定、他のAIへ影響する変更、調査結果、未解決事項とその解決で、詳細は個々の記録へのリンクで示す。変化がなかった定期巡回、細かな操作、連携サービスの本文、秘密情報の値は書かない。構成とルールの変更は従来どおり `changelog.md` に記録し、作業ログとは役割を分ける。
- `10_projects/` は、終わりのある取り組みを置く場所とする。プロジェクトは原則ページ（ファイル）単位とし、1件につき、目的、正本の場所、担当AI、現在の状況、最終確認日、決定事項、関連する記録や資料へのリンクを書く。正本をここに置くかどうかは、プロジェクトごとに決める。ページの更新は、そのプロジェクトの担当AIが節目のたびに行い、大きな流れは `work-log.md` にも残す。プロジェクトページの新設は、本人の指示または本人が承認した作業の一部として行う。プロジェクトが完了したら、要約を残して `40_archives/projects/` へ移す。
- `20_areas/ai-operations/outputs/` は、Hermes の Bot の成果物の出力先とする作業場である。Bot ごとに自分の名前のフォルダを自分の領域とし、他の Bot のフォルダは編集しない。作業中のファイルも入るため、巡回や他の参加者はフォルダ単位で扱い、中身を1件ずつ読まない。成果物のファイルは 2026-11-12 にエイダがここ（当時は 50_projects/hermes）へ移動済み。2026-11-13、本人承認により Hermes 側の6 Botの SOUL・個別登録簿と関連スキルの出力先参照も現行の置き場へ更新し、ファイルを読み戻して確認した。6 Botの新規CLIではrules.md・自己登録簿先を確認し、設定済みの成果物先も回答したが、Desktop／Bot Chatでの保存動作は未確認。
- タスクカード（指示の受け渡し）は当面混ぜない。記録共有だけで始める。ここへの記載自体は、設定変更などの実行許可にはならない。
- OpenCode はモデルの供給と実行経路であり、参加者フォルダは作らない。OpenCode 経由の成果は、実際に作業を指示した側（Bot、Claude Code、エイダなど）のフォルダに、経路とモデル名を明記して置く。
- フォルダ名は「誰が書いたか」（エージェントや Bot の名前）で付ける。使用したモデルや経路（GPT、Claude Code、OpenCode Go など）はフォルダ名にせず、記録の中に明記する。Claude は通常の Claude と Claude Code を分けず、`claude/` にまとめる。
- 各 AI の設定の要約は、`20_areas/ai-operations/agents/` の自分のフォルダに固定名の `settings.md` として置く。現行設定の要約と正本の所在に加えて、そのAIの考え方と自分なりの仕組みも書き、`agents/settings-index.md` をその入口と比較表にする。`settings.md` は実際の設定そのものではなく、内容が食い違う場合は正本を優先する。設定ファイルの写しや抜粋を置く場合も、秘密情報を除いたものだけにする。Hermes の各 Bot は要約を profile.md が担うため settings.md は作らず、マナだけは参加者としての settings.md と Bot としての profile.md の両方を持つ。
- 復旧用の全文コピーは `99_backup/` に参加者別のフォルダを分けて置く。Hermes の6 Bot（default のフォルダ名は `hermes`、ほかは `mana`、`arcana`、`label`、`phantom`、`nayuta`）は、各自の `99_backup/<Bot名>/` に正本と同名の `SOUL.md`、`config.yaml`、`profile.yaml` の全文写しを置く。コピー日と「正本は C 側の Hermes プロフィールであり、これは写し」と分かる注記を同フォルダに置く。置く前に秘密情報の値（`config.yaml` の直書き値を含む）がないことを確認し、含むファイルは置かずに報告する。`memories/`（`MEMORY.md`、`USER.md`）は日次バックアップ ZIP に委ね、`.env` と `auth.json` は置かない。原本を変更した Bot はその変更作業の中で自分の写しも更新することを通常作業とし、各 Bot は自分のフォルダだけを編集する。他 Bot のフォルダには書き込まない。登録簿は引き続き要約であり、写しは追加の層である。共有文書の記載だけで各 Bot の SOUL 上の権限は変更されない。その他の参加者も自分のフォルダだけに秘密情報の値を除いた写しを置き、原本変更時に更新する。
- 構成を変えたら（フォルダや固定ファイルの追加・改名・削除、ルールの変更）、`changelog.md` に1変更1行残す（日付、変更者、内容、他者への影響）。構成の変更は本人の許可が出たときだけ行う。Bot関連の変更についてナユタは自分が実施または実物確認した分を追記でき、マナはナユタの代行として作業した場合のみ同条件で追記できる。その他の参加者による変更の記録は従来の担当に従う。追記のみとし、過去の行は書き換えない。
- スクリプトや skill を追加・移動・削除した AI は、その作業の中で、正本の置き場（スクリプトは AI_knowledge 内の `20_areas/ai-operations/scripts`、skill は同じく `30_resources/skills`）の直下の `index.md` も更新する。スクリプトの実行用コピーは PC 側の `C:\Users\nekol\scripts` に置き、正本を更新したらコピーも合わせる。

## マナの書き込み範囲

- 2026-11-11 の本人の決定により、マナは `20_areas/ai-operations/logs/mana/` と `20_areas/ai-operations/agents/mana/` 内の通常の小規模な追加・編集ができます（2026-11-12 と 2026-11-13 の再編で置き場が変わったもの）。`agents/_template.md` はナユタが対応できない場合に限りマナが代行更新できます。`agents/index.md` はナユタが通常更新し、ナユタが対応できない場合に限りマナが代行します。マナがナユタの代行として作業した場合には `changelog.md` の末尾追記だけを上記の条件で行えます。他の AI の `agents/` フォルダ、`30_resources/knowledge/` のその他の既存ファイル、`20_areas/life/` の月次索引、他の参加者の `logs/` は閲覧のみです。knowledge や月次索引に反映したい内容は `logs/mana/` に置き、担当者へ伝えます。今回の README 修正は本人から個別に許可された例外であり、README への継続的な書き込み権限ではありません。
