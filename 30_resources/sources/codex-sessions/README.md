# Codex セッションログの索引について

## これは何か

Codex のセッションログから機械的に抽出した索引（index.md）の置き場所です。2026-11-15 に本人が「蒸留形で KB 化する（索引と要約だけ AI_knowledge へ）」と決めたものに対応します。

## 原文の場所

- 原文は Drive に入れず、本人の PC の `E:\Documents\archives\sessions` に残してあります。
- 範囲：536 セッション、2026-01-08 から 2026-11-14。形式は Codex の rollout（.jsonl）で、大半は .zst 圧縮されています。
- 原文には、プロンプトと応答に加えて、ツールが読んだファイルの中身やコマンド出力まで含まれます。強い秘密パターンのヒットも 1 件あったため、原文は共有 KB に入れない判断です。原文が必要なときは PC 側で開いてください。

## 索引の作り方

- 抽出は機械処理です（2026-11-15、エイダ）。項目は、開始日時（JST）、作業場所（cwd）、モデル、発言・応答・ツール実行の回数、所要時間、apply_patch で変更されたファイルです。
- 「依頼の要旨」は最初の実質的なユーザー発言の抜粋、「結果の要約」は最後のエージェント応答の抜粋です。LLM による要約ではないので、言い回しは原文のままです。
- 秘密情報らしいパターン（秘密鍵、主要な API キーの形式など）で各欄を検査し、該当する欄は落としています。今回の抽出では該当はありませんでした。
- 変更ファイルは apply_patch 経由のものだけを拾っています。シェル経由の編集は索引に載らないため、載っていないことは「変更が無かった」ことを意味しません。

## 使い方

- 過去の Codex 作業を探すときは index.md を検索してください。月別の見出しで分かれています。
- 詳しい経緯が必要な場合は、行の日時に当たる原文ファイルを PC の archives から開いてください（ファイル名に日時が含まれています）。
