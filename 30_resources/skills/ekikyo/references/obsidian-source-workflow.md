# Obsidian の卦資料と通常占い

## 役割と順序

1. 問い・背景と、Obsidian からコピーした本卦・変爻の原文／読み下し／高島解釈／該当占例がそろっていれば、その貼付資料を優先して通常モードで占いの結論を出す。コピーされた資料は証拠であり、それ自体は占いの回答ではない。
2. Obsidian 側で背景・問いを書いたテンプレートに、筮の結果から特定した本卦・変爻を記入する。略筮法プラグインには6桁の二進数を下から上の爻順で入力し、次行に1〜6の変爻を入力する。本卦・変爻・高島本文・該当占例がクリップボードに出るのでテンプレートの下へ貼り付け、問いと資料を一式としてAIへ渡す。プラグイン単体は質問文も結論も生成しない。中筮法では条件により之卦も含み、5卦モードは卦名一覧であって全文資料ではない。現在の主な流れは略筮法／中筮法から通常モードへの受け渡しであり、古い EXTRACT は存在しても通常の資料調達の前提にしない。
3. 貼付資料に必要な箇所が欠けるときだけスキル内の通常モード参照ライブラリを確認し、参照箇所・ファイル名を明記する。EXTRACT 専用 assets を通常モードの不足埋めに流用しない。
4. 占例は別の問いへの適用例として扱い、特殊な結論や象を今回の相談に直輸入しない。爻辞の肯定的な結びつきを、語感だけで拘束・凶と断定しない。
5. 保管先を聞かれたら、Obsidian の原資料、プラグインに同梱された生成データ、Bot の参照ライブラリ、EXTRACT の入出力、今回貼られた通常占いの資料を分けて確認する。プラグインの資料・Bot の参照資料は新しい占いの自動蓄積先ではない。通常の貼付資料をファイルに保存したと推定せず、指定の出力フォルダの有無と実際に保存したファイルを確認してから答える。

## プラグインの精査（依頼されたときだけ）

1. プラグインの README と実装の `main.js`、データ生成器、同梱 JSON を読む。現在の実装を先に確認し、旧 EXTRACT 仕様と同一視しない。
2. 入力検証、卦・爻の解決、モード別の出力組立、クリップボード転送をコードに沿ってたどる。たとえば略筮法は `resolveHexagram` → `buildSimpleOutput`、中筮法は `resolveHexagramWithZhiGua` → `buildSimple2Output`、5卦は `resolveHexagramSummary` → `buildEx5Output` を確認する。
3. データ件数と欠落を調べ、プラグイン関数を既知の卦・爻で実行して見出し・引用・占例の有無を確かめる。生成器の `build_dataset()` をメモリ上で実行して JSON と照合すれば、配布データを書き換えず検証できる。
4. 配布先プラグインがある場合はコードとデータを別々に比較する。改行コードだけでバイト差が生じるため、JSON は解析後の内容一致も確認する。作業ツリーに変更がある場合は調査だけで同期・再生成・コミットを行わない。
