# EfficientSkill 論文の要点（エージェントのスキルを token 効率よく育てる2段階の方法）

記録日：2026-11-18
きっかけ：DAIR.AI の X ポスト（2026-11-17）で紹介された論文を、エイダが arXiv の要旨で裏取りしたもの。

## 出典

- 論文：EfficientSkill: Learning Skills for Token-Efficient Multi-Turn Agents
- arXiv:2611.19823（2026-11-15 投稿、プレプリント）
- 著者：Deep Shah、Sanket Badhe、Nehal Kathrotia、Priyanka Tiwari

## 論文の主張（要旨に基づく）

### 問題

スキルの自動改善（失敗した実行を見て指示を直す反省型の最適化）は、失敗のたびに例外ルールを足していくため、スキルが膨らんでプロンプトが長くなり、token 消費が増え、エージェントが長く誤りの多いループに入りやすくなる。

### 方法（2段階）

1. 第1段階：長さへのペナルティなしに、失敗の修正を重ねて、目標の正確さに届くスキルをまず作る。
2. 第2段階：そのスキルを起点に、正確さが目標付近から落ちないことを条件として、指示を刈り込む。再利用できるコードは、ワークスペース側のユーティリティへ移し、プロンプト側の実装コストをゼロにする。

空の種から刈り込みを始めると止まってしまうため、この順序（先に正確さ、後で刈り込み）が要だとしている。

### 結果（論文の報告値）

- 対象：4モデル（frontier／中位／オープンウェイト）× MATH-500、ALFWorld、SpreadsheetBench。
- 12条件中11条件で、無制約の EvoSkill より出力 token が減少（最大80%減）。
- 正確さは全ベンチマークで上昇。SpreadsheetBench では Gemini 3.8 Flash で +14.3 ポイント、Grok 4.1 Fast で +17.5 ポイント。
- 生成 token と再生される履歴の両方が縮むため、提供コストは全条件で低下。

## こちらの運用への関係（エイダの見立て）

- Hermes Agent の学習ループ（スキルと記憶を Bot 自身が書き足す仕組み）は、この論文の言う「膨らむ側」の動きそのもの。2026-11-17 に全 Bot で write_approval を有効にし、書き込みを承認制にしたのは、この膨張への関所として位置づけられる。
- スキルの維持は「足すだけ」で終えず、ある程度育った段階で、正確さを落とさない範囲で刈り込む第2段階を設ける、という考え方が参考になる。Muse 側のスキル昇格ゲート（検証済みの成功、失敗パターンの名前、除外した行き止まりの記録）とも方向は合う。
- yomiyasu や ekikyo のような正本スキルは人がキュレーションしているため自動最適化の対象ではないが、「再利用できる処理は本文ではなく道具（スクリプト）側へ寄せる」という分離は、既に yomiyasu の検査スクリプトの形で実践している。
