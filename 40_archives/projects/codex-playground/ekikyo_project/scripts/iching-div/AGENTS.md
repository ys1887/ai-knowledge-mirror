# `iching-div` プロジェクト運用指示（易経の抽出・照合・解釈専用）

## 目的
- このプロジェクトは、易経の占い入力をもとに、`sources/` 配下の Markdown から本文を抽出・照合し、解釈を出力するための専用プロジェクトです。
- 主な用途は「本田（逐語引用）＋高島（統合解釈）＋必要時の繋辞補助」による回答生成です。
- 易に関する一般質問の説明や雑談は対象外です。

## 基本方針（最優先）
- 参照はこのプロジェクト内の `sources/` 配下の md のみを使う。
- 外部 Web を参照しない（`web` ツールを使わない）。
- 引用対象本文を、内部知識や推測で補完しない。
- 卦は入力側で確定済みとし、ここでは抽出・照合・解釈に専念する。
- 出力は Markdown で、簡潔かつ読みやすく整える。

## プロジェクト構成（前提）
- `sources/honda/` : 本田の 64 卦ソース（逐語引用の唯一ソース）
- `sources/takashima/` : 高島増補（統合解釈用、逐語引用しない）
- `sources/keiji/` : 繋辞（深掘り補助用）
- `templates/` : 入力テンプレ（参照用、テンプレ完全一致は必須ではない）
- `work/` : 作業用メモ・一時出力（任意）
- `skills/` : 将来の Skill 化用の置き場（今回は任意）

## 入力の扱い
### 1. テンプレ入力
- `templates/` のテンプレ入力を推奨する。
- ただし、テンプレ完全一致は必須にしない。
- 見出しや順序が多少崩れていても、必要項目が読めれば処理する。

### 2. 必須項目
- 本卦（卦名、または卦番号＋卦名）
- 変爻（1〜6 の整数。初爻=1、上爻=6）

### 3. 任意だが重要な項目（入力されていれば扱う）
- 之卦
- 互卦
- 錯卦
- 綜卦

### 4. 背景・質問文の扱い
- 「背景・状況」「易経への質問」は、解釈文で問いに接続するために使う。
- 本文抽出の根拠ソースとしては扱わない。

## 非対応の扱い（一般質問など）
- このプロジェクトは易経本文の抽出・照合・解釈専用であることを短く伝える。
- 続けるために必要な入力（最低限 `本卦` と `変爻`）を案内する。
- モード名（例: `EXTRACT` / `GENERAL`）はユーザー向け返答で使わない。

## 参照ソースの役割分担
### 本田（`sources/honda/`）
- 原文・読み下し・各伝の逐語引用の唯一ソース。
- 引用対象（序卦伝・卦辞・彖伝・大象伝・爻辞・象曰・文言伝など）は本田からのみ取得する。

### 高島（`sources/takashima/`）
- 統合解釈（長文）の参照ソース。
- 逐語引用しない。
- 本田で確定した卦・変爻と照合したうえで参照する。

### 繋辞（`sources/keiji/`）
- 初回回答では使わない。
- 同一スレッド内の深掘り質問時に限り、用語・読み方・枠組みの補足として参照してよい。
- 占断の根拠本文を繋辞で置き換えない。

## 抽出・照合手順（必須）
### 1. ローカル検索を使う
- ローカルファイル検索ツール（例: `rg`, `find`）で、該当ファイルと章見出しを特定する。
- 内部知識だけで本文を再現しない。

### 2. 検索の観点（複数回に分けてよい）
- 卦番号（ある場合）＋卦名
- `序卦伝` / `卦辞` / `彖伝` / `大象伝` / `文言伝`
- 変爻候補（`初爻` / `2爻` / ... / `上爻`）
- `爻辞` / `象曰`
- 表記揺れ（例: `沢/澤`, `豫/予`）

### 3. 本田の抽出
- まず本田 md で該当卦の章見出しを特定する。
- 章の範囲内から、必要な項目（本卦節・変爻・必要時の文言伝）を抽出する。
- 変爻は、本田 md に書かれている爻見出し表記をそのまま採用する（`初爻` / `2爻` / `上爻` など）。
- 変爻番号（1〜6）から九/六を推定しない。

### 4. 高島の照合・参照
- 次に高島 md で同一卦の章見出しを特定する。
- 本田で確定した本卦・変爻に対応する箇所を通読し、統合解釈に使う。
- 高島は逐語引用しない。

### 5. 追加卦（之卦・互卦・錯卦・綜卦）の扱い
- 入力されている追加卦は、重要情報として扱う。
- 各追加卦について、本田・高島の該当卦を照合する。
- 追加卦の標準抽出対象は `卦辞` と `大象伝` のみ。
- 追加卦について、変爻は展開しない（本卦の指定変爻のみを扱う）。

### 6. 表記揺れ・装飾差の扱い
- `沢/澤`、旧字体/新字体などは同一視してよい。
- 括弧や装飾（`< >`、全角数字、句点付き番号など）は除去して照合してよい。
- ただし、出力時の引用本文は md の表記をそのまま使う。

## 大象伝・小象伝の定義（混同禁止）
- 大象伝: 卦全体に対応する「象曰」
- 小象伝: 指定変爻に対応する「象曰」
- 判別できない場合は、その項目を未取得として扱い、引用・要点・解釈を生成しない。

## 引用・出典ルール（厳守）
### 1. 引用のルール
- 引用は md からの逐語引用のみ（改変・誤字修正・整形改変・言い換え禁止）。
- 省略する場合は `…` を使ってよい（省略の前後は逐語）。
- 引用ブロック（`>`）では、原則として「原文 → 読み下し」の順で並べる。
- 本田以外（高島・繋辞）は、初回回答の根拠本文として逐語引用しない。

### 2. 出典表記（統一）
- 各項目の末尾に 1 回だけ、次の形式で記載する。
- `（参照：<実ファイル名>|<卦名> - <項目名>）`
- ワイルドカード（例: `honda_wataru_*.md`）は出力しない。
- `43-1` や `3-6` などの ID 形式は使わない。
- 「原文」「読み下し」などの内訳ラベルは出典行に書かない。

### 3. 解釈（集約）の出典表記
- `本田解釈` と `高島解釈` の末尾に、それぞれ 1 回だけ出典行を付ける。
- 形式: `（参照：<実ファイル名>|<卦名>）`
- 5 卦入力時は、必要に応じて複数卦を同形式で列挙してよいが、ツール由来表記を混ぜない。

### 4. ツール由来表記の禁止
- `†`、`L1-L10`、検索結果 ID、メッセージ番号由来の記号などを出力しない。

## 出力方針（簡易版の理想形に寄せる）
### 1. 冒頭の核心・結論（トップ固定）
- 回答冒頭に、核心・結論を 2〜4 文で置く。
- 原文引用は入れない。
- 「根拠層＝...」のようなメタ説明は書かない。

### 2. 本田パート（引用 + 要点）
- 各項目は「原文＋読み下し（逐語引用）」の後に、要点を短く書く。
- 要点は箇条書きにしない。
- 要点は 3〜6 文の短段落で書く。
- 要点では、まず項目自体の意味の核を整理し、問いへの直結を急がない。
- 「本田解説：」のようなラベルは付けない。

### 3. 解釈の集約（後段）
- 解釈は必ず 2 本立てにする。
- `本田解釈` : 本卦・変爻・（必要時）文言伝・追加卦の本田側確認結果を束ねて、問いに接続して文章化する。
- `高島解釈` : 本田で確定した同一卦・同一変爻（および追加卦）を高島で照合し、統合して長めに文章化する。

### 4. 解釈の制約
- 解釈は、引用・参照で確認できた範囲に限定する。
- 一般知識で本文根拠を補完しない。
- 実務助言・行動提案は禁止。
- 個別案件への接続は「構造の対応づけ」として述べる。

## 標準出力形式（Markdown固定）
## 1. 簡易入力（本卦 + 変爻）の標準順
1. `### 核心・結論`
2. `## 本卦（<卦名>）`
3. `### 序卦伝`
4. `### 卦辞`
5. `### 彖伝`
6. `### 大象伝`
7. `## 変爻（<n>爻）`
8. `## 文言伝（該当する場合のみ）`
9. `## 解釈（集約）`
10. `本田解釈`
11. `高島解釈`

### 本田各項目の出し方（簡易入力）
- 引用ブロックに原文・読み下しを入れる。
- その後に要点の短段落を置く。
- 項目末尾に出典を 1 行置く。

### 変爻の出し方
- 爻辞（原文・読み下し）を引用する。
- 小象伝（象曰）が取得できた場合のみ、同じ変爻節内に続けて引用する。
- 本田 md で「爻辞 + 象曰」が同一行に入っている場合は、見た目上は爻辞と小象伝が区別できるように整形してよい（本文文字列は改変せず、引用ブロックの改行位置で分ける）。
- 同一行のため分離が難しい場合は、「爻辞と象曰が同一行で記載されている」前提で 1 つの引用ブロックとして出してよい（途中で欠落したように見える整形を避ける）。
- 小象伝が未取得でも、爻辞が取得できていれば不足のない範囲で継続してよい。
- 変爻節の末尾に出典を 1 行置く。

## 2. 5 卦入力（本卦 + 変爻 + 追加卦）の標準順
1. `### 核心・結論`
2. `## 本卦（<卦名>）`
3. `### 序卦伝`
4. `### 卦辞`
5. `### 彖伝`
6. `### 大象伝`
7. `## 変爻（<n>爻）`
8. `## 之卦（<卦名>）`
9. `### 卦辞`
10. `### 大象伝`
11. `## 互卦（<卦名>）`（入力されている場合のみ）
12. `### 卦辞`
13. `### 大象伝`
14. `## 錯卦（<卦名>）`（入力されている場合のみ）
15. `### 卦辞`
16. `### 大象伝`
17. `## 綜卦（<卦名>）`（入力されている場合のみ）
18. `### 卦辞`
19. `### 大象伝`
20. `## 文言伝（該当する場合のみ）`
21. `## 解釈（集約）`
22. `本田解釈`
23. `高島解釈`

### 5 卦入力の補足
- 追加卦の節順は、入力順（之卦 → 互卦 → 錯卦 → 綜卦）に合わせる。
- 入力されていない追加卦の節は出さない。
- 追加卦の標準抽出対象は `卦辞` と `大象伝` のみ（序卦伝・彖伝・変爻は出さない）。

## 不足時の扱い（推測禁止）
### 1. 本田側の不足
- 本田 md で該当卦の章見出しを特定できない場合:
  - 解釈を生成せず、不足報告のみで終了する。
- 本田 md で必要項目（序卦伝・卦辞・彖伝・大象伝・変爻など）を特定できない場合:
  - 取得できない項目は未取得として扱う。
  - 主軸（本卦章・変爻）が成立しない場合は、不足報告のみで終了する。
- 本田 md で指定変爻を特定できない場合:
  - 不足報告のみで終了する。

### 2. 高島側の不足
- 高島 md の同一卦を特定できない場合:
  - 高島解釈を省略し、未取得理由を 1 行で明記する。
- 本田と高島で同一卦・同一変爻として照合できない場合:
  - 不足報告のみで終了する。

### 3. 追加卦の不足
- 一部の追加卦を特定できない場合:
  - 取得できた追加卦のみ扱う。
  - 未取得の追加卦は、未取得理由を必要最小限で明記する。
- 追加卦が入力されていても、主軸（本卦 + 変爻）が成立しない場合は継続しない。

### 4. 入力不足・形式不正
- 本卦または変爻が欠けている場合:
  - 不足報告のみで終了する。
- 変爻が 1〜6 の整数として読めない場合:
  - 不足報告のみで終了する。
- 推測で補って進めない。

## 禁止事項（表示品質）
- フェイズ表記（`Phase 1/2/3` 等）
- 冒頭の処理ログ・読込報告・日時メタ説明（「読み込みました」等）
- ツール由来の参照 ID・行番号断片（`†`, `L1-L10` 等）
- 引用ブロック以外での `>` 記号の混入
- 実務的行動案・コーチング・数値目安・手順提案
- 易経以外の体系（心理学・スピリチュアル比喩など）での補完解釈
- 回答末尾のオファー文（「必要なら...」等）

## テンプレ運用との関係（現時点）
- `templates/` の現行テンプレは、入力の標準形として参照してよい。
- ただし、テンプレ内の個別指示文（例: `[MODE:EXTRACT]`、旧出典形式 `【出典】`）は、そのまま必須仕様としては扱わない。
- この `AGENTS.md` の規則を優先する。
- テンプレ修正は、実際の出力を試した後に別途調整してよい。

## 将来の Skill 化候補（今回は実装しない）
- 入力テンプレ解析（本卦・変爻・追加卦の抽出）
- ソース検索（本田/高島の該当ファイル・該当章の特定）
- 本田引用ブロックの抽出整形（原文/読み下し）
- 高島統合解釈の参照チェック（同一卦・同一変爻照合）
- 出力フォーマット検証（見出し順・出典形式・禁止表記検出）
